# Steward

Back to the [README](../README.md).

With a Claude Code conversation in front, tick other Claude Code conversations or OpenCode Agent Plus conversations in the Steward panel to make the conversation in front their steward. The conversations you tick can be in any VS Code window on this machine. The Steward panel is at the bottom of the VS Code window, in the panel area beside Problems, Output and Terminal. The panel lists the Claude Code conversations open in your VS Code windows, one group per window, followed by the open OpenCode Agent Plus conversations in one group named OpenCode Agent Plus. OpenCode Agent Plus registers its conversations with Agent Plus, an extension it shares with Claude Code Plus. Agent Plus does not report which window has each OpenCode Agent Plus conversation open. When a Codex conversation is in front, the panel says that it cannot be a steward or be managed by one and shows no ticks to change. When an OpenCode Agent Plus conversation is in front, the panel shows no ticks to change. It says that the conversation cannot be a steward and that you can bring a Claude Code conversation to the front and tick the OpenCode Agent Plus conversation there. Bringing a Claude Code conversation to the front brings the list back, while file and other non-conversation tabs leave the panel on the last Claude Code conversation. Turn on **All, including new ones** to have this steward manage all conversations in the list and any opened later, except other stewards and conversations another steward ticked. While the switch is on, the checkboxes in the list are disabled.

A conversation has one steward at most, and a steward has none. In a steward's panel, the box of another steward is greyed, and so is the box of a conversation another steward ticked; such a row says "a steward" or "managed by" followed by the steward's name. Click that name to open the steward's conversation. Hover over the box to see the full reason. A conversation that becomes a steward leaves the list of the steward that had it. Only one steward at a time can have **All, including new ones** on; while it does, the switch is greyed in the other stewards' panels and names that steward beside it. If a steward manages a conversation only through All, another steward can take it over by ticking it. If a list from an earlier version of Claude Code Plus breaks these rules, the first window allowed to write the list (see [Known limits](known-limits.md#steward)) saves the same result that windows use when they read it: a conversation that is a steward leaves every list; for a conversation on several lists, stewards that ticked it take priority over those that have it only through All. Among the stewards that ticked it, the one whose list changed most recently keeps the conversation. If several stewards have All on, the one whose list changed most recently keeps All on. The others keep their lists with All off.

A steward keeps its own title in its tab and session list row, with one crown (👑) drawn after the title whatever you type. The crown is just for display, so it stays out of the rename box and renaming cannot keep or double it.

Each message you send the steward comes with what each of the conversations it manages is doing. Start a message with `@` and a conversation's name, or ask the steward to tell one of them something, and the steward writes the message for that conversation in its own words. Claude Code Plus types it into that conversation and sends it, so it counts there as your own message, including when it approves something, such as a plan or a change. In its replies, conversation names and session IDs link to the conversation in whatever window has it; see Links to other conversations in [Other features](features.md#in-a-conversation). You can ask the steward to rename or close a conversation it manages. You can also ask it to start a new conversation in a project open in a VS Code window, with the first message you want it to get. It tells you if no such window is open. The first message in the new conversation counts as your own, and the steward then manages it. Closing a conversation closes its editor tab without deleting anything, and you can reopen it from the session list. If the conversation is working, waiting for an answer, or running background work, the steward asks you again and closes it only if you agree. If you name a conversation that no VS Code window has open, the steward can reopen it in an editor tab and pass your message to it. Claude Code stores each conversation under the folder where it was last opened. The tab opens only in the window that lists that folder first in its workspace; Claude Code looks for a window's stored conversations there alone, and in any other window would start a new, empty one. If a window or another process is already running the conversation, the steward does not open the tab. A conversation the steward reopens is then ticked for it in the Steward panel. When a managed conversation hands the steward a message that does not belong there, the steward first checks your own words in that conversation. It passes them to the right conversation or to a new one, then tells you where the message went. The handoff goes to the conversation's steward, or, if no steward ticked it, to the steward with All on.

A managed conversation knows a steward is watching, and leaves its questions for you in its work plan rather than messaging the steward. The steward passes that conversation's questions to you word for word. Claude Code Plus sends the steward a notice when a managed conversation needs you or stops while an open row in the steward's own work plan names it. It also sends a notice if a managed conversation has a background session or `claude -p` worker that ended without finishing. "Stops" means the turn has ended, no background work is left, and that is still so two seconds later. The wait keeps a conversation that starts its next turn at once, for a message you sent while it was working, from counting as stopped. For a conversation waiting on a permission prompt, the steward is told which command it is for, and each question is passed to the steward once. When nothing in a notice needs you, the steward replies with only `[[quiet]]` or a single dash. The Claude Code panel where the steward conversation is shown hides such a reply, along with the folded row of tool calls just before it.

You can tick an OpenCode Agent Plus conversation in the Steward panel to let the steward manage it. Only a Claude Code conversation can be the steward. OpenCode Agent Plus registers its OpenCode conversations with Agent Plus, the extension it shares with Claude Code Plus. The panel lists those conversations only when both OpenCode Agent Plus and Agent Plus 1.5.0 or later are running in the VS Code window that shows the steward. Agent Plus in that window supplies the list and the location of each conversation's work plan, and passes messages. Click a conversation's name to have Agent Plus open it in the window that shows it. To rename, close or reopen it, use its own window. The steward can't do that for you.

As with a Claude Code conversation, you can ask the steward to send a message to a managed OpenCode Agent Plus conversation. The steward writes the message. Claude Code Plus passes it to Agent Plus, which delivers it to OpenCode Agent Plus in the window where the conversation is open. It appears there as your own message. If the conversation is waiting for you to approve a tool or answer a question, it won't accept the message, and the steward tells you so. Only you can respond in that window. When the conversation starts waiting for you, the steward gets a notice just as it does for a Claude Code conversation. The notice names the tool that needs approval or says a question is waiting. The steward also gets a notice when the conversation stops if an open row in the steward's own work plan names it. The steward can read the conversation's work plan, its latest reply and your latest messages there. OpenCode Agent Plus writes the reply and messages to a file beside the plan at the end of each turn. With Agent Plus 1.6.0 or later and an OpenCode Agent Plus release later than 1.0.0, a managed OpenCode Agent Plus conversation is told each turn that a steward watches it. Like a Claude Code conversation, it can hand the steward a message it thinks belongs elsewhere, provided it is open in a VS Code window.

On Linux, when Claude Code runs a conversation in more than one process at once, as after a window went away while its extension host stayed, the conversation is marked in the Steward panel and the session list and the steward is told each process's pid, start time and window. Claude Code keeps a conversation's transcript in a folder for the directory it runs in. If the conversation continues from another directory, each folder has a copy. A window open on the other folder resumes the older copy. When the processes run copies in different folders, Claude Code Plus compares the copies as they stood when the later process started. If one copy's newest entry was at least ten minutes older than the other's newest entry, the process running the copy that was furthest behind is the old process, regardless of which process started first. If neither copy was that far behind, the panel offers no button and Claude Code Plus does not stop either process without asking. If another window shows a conversation and this window does not, clicking the conversation in this window's session list brings it to the front in the other window instead of opening it here. Claude Code Plus stops the old process when it is idle and its window is gone, and tells the steward; otherwise the panel's Stop the old process button does it. The process that keeps the conversation is told which background commands, monitors and subagents stopped with the old one.
